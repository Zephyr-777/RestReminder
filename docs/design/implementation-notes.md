# 实现笔记（旧版 README 存档）

> 这份是开发过程中的实现记录，接口与目录可能已经变化。面向使用者的说明请看仓库根目录的 [README](../README.md)。

专为 macOS 设计的原生轻量级状态栏（Menu Bar）应用，常驻屏幕右上角，不占 Dock 栏空间。

## ✨ 核心特性

- **🌱 渐进式微休息（打破僵局·低阻力）**：
  - **眼科临床泪膜重涂机制**：盯屏幕时人眨眼频率会暴跌 60% 以上，且不完全眨眼超过 50%，导致干眼、视疲劳。微休息每 15 分钟轻柔提示一次，持续 10~15 秒。
  - **15 秒四步动作引导**：
    - `0~2.5s`：**闭紧双眼 2 秒**（上下睑缘完全闭合贴合，机械泵压睑板腺分泌脂质）
    - `2.5~6s`：**自然睁开 · 缓慢眨眼**（脂质层均匀覆盖眼表，完成完整泪膜重涂锁水）
    - `6~结束前4s`：**远眺 6 米以外**（这几秒不看手机，让睫状肌彻底松开）
    - **最后 4 秒**：**记得多眨眼** —— 收尾提示，图标本身会眨两下（`eye.fill` ⇄ `eye.half.closed.fill`）。
      从遮罩回到内容的那一刻注意力立刻被占满，最容易忘的就是眨眼，所以这句话放在最后一屏而不是开头。
  - **极简退出保障**：按 Esc、空格、回车或任意键，或轻点鼠标，即可瞬间平滑淡出，绝不强行锁死，打破抵触心理。
- **🎯 双轨防护（默认全开）**：每 15 分钟一次 15 秒微休息重涂泪膜，叠加每 45 分钟一次的大休息（呼吸光晕 / 强制熄屏），两档同时生效，无需分级切换。
- **😌 眨眼节律（每 5 分钟）**：不弹窗、不出声、不遮挡，只让菜单栏那只眼睛眨一下，两次之间缓缓变暗当进度条。可选的屏幕边缘极淡呼吸（默认关）。详见 [眨眼节律](#-眨眼节律每-5-分钟不打断注意力)。
- **右上角状态栏图标（眼睛系列）**：原生适配 macOS 浅色/深色主题，用眼睛的开合表达状态：
  - 👁 **专注中**（`eye.fill`，睁眼）：正在活跃计时
  - 🌱 **微休中**（`eye.circle.fill`，圆环眼睛）：正在进行 15 秒泪膜重涂微休息
  - 😑 **离开中**（`eye.half.closed.fill`，半闭眼）：检测到离开电脑已暂停走表
  - ⚠️ **大休中**（`eye.trianglebadge.exclamationmark.fill`，眼睛+警告）：到达大休息时间
- **多信号在场判定**（不再只看键鼠空闲）：
  - 屏幕熄灭或锁屏立即暂停，媒体播放持有断言时照常计时，无操作超时兜底。
- **极速与低耗**：纯原生 Swift 编译，约 180KB，内存约 10MB，CPU 占用 0.0%。

## 📂 项目结构

代码按职责拆成了多个文件（`Sources/`）：

```
Sources/
  main.swift               入口（启动和调试 flag 检测）
  AppDelegate.swift        主逻辑：微休息与大休息双轨调度、菜单、在场判定
  MicroBreakOverlay.swift  微休息全屏指引（闭眼泵压 → 泪膜重涂 → 远眺 → 收尾眨眼提示）
  BlinkReminder.swift      眨眼节律（菜单栏眨眼动画 + 渐暗进度 + 可选边缘光晕）
  BreakOverlay.swift       大休息全屏提醒动画 + 循环休息画面（含倒计时）
  OverlayWindow.swift      遮罩窗口类（接管键盘、覆盖多屏）
  Presence.swift           在场判定（PresenceDetector + Presence 枚举）
  Config.swift             配置键、@propertyWrapper 设置项、视觉样式常量
  Stats.swift              每日用眼统计（每秒累积 → JSON 落盘）
  Logging.swift            调试日志（带轮转）
tools/
  daily_report.py          每日播报生成器（读统计 → Material 风格 HTML）
reports/                   生成的播报 HTML，一天一个
```

构建：`./build.sh` 会编译 `Sources/` 下所有 `.swift`。

**几个约定：**

- **配置项**用 `@propertyWrapper`（`BoolSetting` / `IntSetting` / `DoubleSetting`）。
  改默认值只改 `AppDelegate.swift` 顶部那一行，不要再写重复的 getter/setter。
- **视觉常量**集中在 `Config.swift` 的 `Style` 里（背景、主色、文案色、光晕位置）。
  这里的数值和 `assets/render-breath.swift` 是**同一组**，改配色时两处都要改。
- **日志**有轮转：超过 512KB 自动截断到最近 2000 行，不会无限增长。
- 旧的单文件版本保留在 `main-v1-monolith.swift`，只作参考，不参与编译。

## 📊 每日用眼播报

**菜单栏里直接看**：`📊 用眼报告` → 点开子菜单第一行就是今日摘要（`今日已用眼 5 小时 33 分 · 微休息 16 次`），
下面「打开今日报告 / 打开昨日报告」会在后台生成 HTML 并直接用默认浏览器打开，不用碰命令行。
`⌘D` 是今日报告的快捷键。

`Stats.swift` 每秒把「这一秒在干什么」记一笔，按天落盘：

```
~/Library/Application Support/RestReminder/stats/2026-10-19.json
```

只存**原始累积量**（秒数、次数、24 个小时桶），达成率、风险指数这类派生指标留给播报脚本算，
以后想换口径不用改 app 也不用重装。

字段：`screenSeconds` / `awaySeconds` / `pausedSeconds`、
`microTriggered` `microCompleted` `microRestSeconds`、
`longTriggered` `longCompleted` `longRestSeconds`、
`hourlyScreen[24]` / `hourlyBreaks[24]`、`firstScreenAt` / `lastScreenAt`、`longestSessionSeconds` / `sessionCount`。

生成播报：

```bash
python3 tools/daily_report.py                    # 今天
python3 tools/daily_report.py --date 2026-10-18  # 指定某天
python3 tools/daily_report.py --days 30          # 趋势窗口拉长到 30 天
```

产出 `reports/YYYY-MM-DD.html` —— 单文件、无外链、可离线打开。三部分：

1. **屏幕使用时间**：KPI 四联 + 24 小时用眼强度柱图（悬停看每小时明细）+ Apple 系统口径的分应用明细卡片（Top 6 横条 + 两套口径对照）
2. **休息时间**：一天时间构成的环形图 + 双轨休息执行进度条
3. **用眼状态**：眼疲劳风险指数（总时长 30 / 最长连续 25 / 休息缺口 25 / 夜间 20 加权）+ 近 14 天趋势 + 今日 vs 近 7 天日均

> 旧数据从 `debug.log` 的在场判定事件回溯估算（趋势图里画成空心点），
> 新版实测的日期是实心点。同一个小时两份数据都有时取较大值，不叠加。

### 接入 Apple 自带的「屏幕使用时间」

播报还能并排显示系统自己的统计（分应用明细、应用切换次数、24 小时分布），数据直接从 macOS 的
`knowledgeC.db` 里读：

```bash
python3 tools/screentime.py --diagnose   # 看有哪些数据流 / 验证权限
python3 tools/screentime.py --days 30    # 批量导出最近 30 天
python3 tools/screentime.py --date 2026-10-18
```

这个库受 TCC 保护，**需要给 WorkBuddy「完全磁盘访问权限」**（系统设置 → 隐私与安全性 →
完全磁盘访问权限 → 添加 WorkBuddy → 重启 WorkBuddy 生效）。没授权时播报里会显示一条提示，
其余部分照常生成。

导出结果落在 `~/Library/Application Support/RestReminder/screentime/YYYY-MM-DD.json`。
`daily_report.py` 生成时会自动刷新当天那份（超过 15 分钟就重跑一次），历史日期不重导。

**两个踩过的坑**（改代码时别再踩）：

- **别用 `cp` / `shutil.copy2` 复制这个库**。系统 `copyfile(3)` 那条路会被 TCC 直接拒掉（EPERM），
  但 Python 自己的 `open()` 是允许的。所以读取器优先用 `file:...?mode=ro` 只读直连原库，
  真被写锁挡住时再退回 Python 逐块拷贝快照。
- **`ZSTARTDATE` 是 UTC 秒数（2001-01-01 起算）**，换算完必须立刻 `.astimezone()`。
  直接用 UTC 的 `.hour` 分 24 小时桶，整张图会偏移一个时区差（北京偏 8 小时）。
  库里还有少量异常值，换算时得兜住，否则抛 `OverflowError` 把整轮导出带崩。

> **口径差异**：Apple 按「应用处于前台」逐段累加，本工具按「是否在场」判定。看视频、开会、
> 长时间读文档时手不动，本工具照算，Apple 可能因切后台而少算。卡片里会把两个数并排放，
> 差得多的那天，通常就是「盯着屏幕但没在操作」的状态。

> ⚠️ **跨设备（iPhone / iPad）拿不到**：Apple 没有开放任何 API，跨设备数据走 CloudKit
> 私有容器 —— 本机 `~/Library/Caches/CloudKit/com.apple.ScreenTimeAgent` 下只有空目录骨架，
> 是个壳，没有记录。只有「系统设置 → 屏幕使用时间」的界面能看。
> 想要手机数据，只能截图给我读，或手动报数字。
> 另外 macOS 不写 `/device/isLocked` 这条流，所以「解锁次数」在 Mac 上恒为 0，别指望这个指标。

## 🌱 渐进式微休息（Micro-break）与泪膜重涂机制

### 临床眼科与人体工学背景

临床上「20-20-20 法则」（每 20 分钟眺望 20 英尺外 20 秒）是眼科公认缓解**睫状肌痉挛**与**视疲劳**的非药物干预金标准。然而，传统护眼提醒工具往往让人难以坚持：

1. **心理阻力与心流中断**：上来就设 5 分钟大休息强制锁屏，打断深度工作，极易让人抓狂并迅速放弃。
2. **干眼症的核心病理**：长时间注视屏幕时，眨眼频率由正常的 15~20 次/分钟骤降至 5~7 次/分钟，且超过 50% 属于上下眼睑未接触的「不完全眨眼」。这导致**睑板腺（Meibomian Glands）失去眼轮匝肌机械挤压**，脂质无法排出，泪膜水液层迅速蒸发，造成干眼与灼痛。

### 渐进式双轨制解决方案

RestReminder 引入了类似 Stretchly 的双轨微休息机制，并针对临床动作做了严格的节拍引导：

| 维度 | 🌱 微休息（Micro-break） | ☕️ 大休息（Long-break） |
|---|---|---|
| **核心定位** | 打破心理僵局、重涂眼表泪膜 | 肌肉伸展、深度休息与眼肌放松 |
| **触发频率** | 每 **15 分钟**（可选 10 / 15 / 20 分） | 每 **45 分钟**（可选 40 / 45 / 50 分） |
| **持续时间** | **15 秒**（可选 10 / 15 / 20 秒） | **5 分钟**（可选 3 / 5 / 10 分钟或不限时） |
| **动作要求** | **闭眼 2 秒泵压 + 自然睁开重涂 + 远眺 6 米** | 起身走动、喝水、深呼吸、看远方 |
| **打扰程度** | **极低**（类似抿一口水，按 Esc / 任意键即退） | **中/高**（全屏呼吸光晕或显示器断电） |

### 上手方式：默认即最优

安装后无需任何配置，两档休息直接同时生效：

- **微休息**：每 15 分钟弹一次 15 秒指引。这 15 秒**不要看手机**，跟随屏幕节拍：
  1. 前 2 秒紧闭双眼，上下睑缘完全贴合，泵压排油；
  2. 缓慢睁开自然眨眼，重涂泪膜；
  3. 剩下的时间远眺窗外；
  4. 最后 4 秒切到「记得多眨眼」，图标当场眨两下 —— 收起遮罩前把这句话留在眼里。
- **大休息**：每 45 分钟一次，进入呼吸光晕循环画面（或直接熄屏），起身走动、喝水、看远。

觉得某一档太频繁，就在菜单里单独关掉或调整周期 —— 两档互不依赖，各调各的。

## 😌 眨眼节律（每 5 分钟，不打断注意力）

### 为什么不做成弹窗

这个提醒一小时要出现 12 次，是整套机制里频率最高的一个。**任何「弹出来的东西」在这个频率下都会失效**：
第一次还算有效，第三次就变成噪音；更糟的是它会把注意力从正在做的事上拽走 —— 而被拽走之后，
人反而更频繁地忘记眨眼，与初衷相反。

所以这里刻意放弃了弹窗、系统通知、声音、全屏遮罩，只走**周边视觉**通道，分三层，一层比一层轻：

| 层级 | 表现 | 为什么有效 | 默认 |
|---|---|---|---|
| **1. 菜单栏眨眼**（主通道） | 菜单栏那只眼睛做一次 0.8 秒的闭合动画：睁 → 半闭变暗 → 睁开 | 看到「眼睛闭上」会诱发**镜像性眨眼反射**，比自己读一行「请眨眼」快得多，且完全不占认知资源 | 开 |
| **2. 图标慢慢变干**（过程提示） | 两次眨眼之间，图标最后 30% 的时间里从全亮降到 60% | 图标本身变成进度条：越淡 = 越该眨眼。余光扫到就顺手眨一下，**不需要任何东西"提醒"** | 开 |
| **3. 屏幕边缘呼吸**（可选） | 只在最外圈 130pt 内做一圈峰值 5% 的提亮，1.2 秒淡入 / 0.6 秒保持 / 1.2 秒淡出 | 周边视觉能捕捉到，但中心内容一像素都不遮挡，视线不会被拉走 | **关** |

### 动画时间轴

20 帧 × 40ms = 0.8 秒：

```
帧  0–5   睁眼，保持
帧  6–8   快速闭合（换 eye.half.closed.fill，alpha 0.55）
帧  9–11  闭住（alpha 0.30，最暗）
帧 12–15  睁开（alpha 0.85）
帧 16–19  恢复全亮
```

### 只在你真的在看屏幕时才提醒

累计只在「在场判定 = focusing / watching」时走。走开、锁屏、正在微休息/大休息时全部冻结；
微休息或大休息结束后**重新起算** —— 眼睛刚湿润过，不该一回到屏幕就催你眨眼。

### 菜单里能调什么

`👁️ 眨眼节律` 子菜单：开关、间隔（3 / 5 / 10 / 20 分钟）、是否开启边缘光晕、演示一次。

> 想立刻看效果：菜单里点「👁 演示一次眨眼」，或者 `touch /tmp/rr_preview_blink.flag`。

## 🚶 离开判定（在场检测）

### 为什么改

旧版只有一条规则：**键鼠空闲 3 分钟就暂停计时**。问题是「键鼠没动」不等于「人不在」：

| 场景 | 键鼠 | 眼睛 | 旧版判定 | 应该 |
|---|---|---|---|---|
| 看 B 站/YouTube 视频 | 十几分钟不动 | **一直在看** | 判成离开，停止计时 ❌ | 继续计时 |
| 开线上会 / 听网课 | 不动 | **一直在看** | 判成离开 ❌ | 继续计时 |
| 盯着代码或文档思考 | 几分钟不动 | **一直在看** | 判成离开 ❌ | 继续计时 |
| 去倒水 / 接电话 | 不动 | 没在看 | 暂停 ✅ | 暂停 |
| 合盖走人 | 不动 | 没在看 | 要等 3 分钟才暂停 | 立即暂停 |

也就是说，旧版在**最该提醒的时候（长时间盯屏幕）反而沉默**，这对护眼工具是硬伤。

### 现在的判定方式

按「证据强度」从高到低排优先级：

| 优先级 | 信号 | 判定 | 计时 |
|---|---|---|---|
| 1 | 显示器已休眠（`CGDisplayIsAsleep`） | 离开 · 屏幕已熄灭 | 暂停，唤醒后清零 |
| 2 | 屏幕已锁定（`CGSessionCopyCurrentDictionary`） | 离开 · 屏幕已锁定 | 暂停，唤醒后清零 |
| 3 | **有程序持有防熄屏断言**（`IOPMCopyAssertionsStatus`） | **屏幕内容播放中 · 仍计时** | **继续累加** |
| 4 | 无操作 ≥ 15 分钟（屏幕还亮着） | 离开 · 已自主休息 | 清零 |
| 5 | 无操作 ≥ 阈值（默认 5 分钟） | 离开 · 长时间无操作 | 暂停 |
| 6 | 以上都不满足 | 专注中 | 继续累加 |

两个关键点：

- **优先级 3 是核心改进**：视频播放器、Keynote/PPT 演示模式、Zoom/腾讯会议运行时都会持有 `PreventUserIdleDisplaySleep` 断言。读这个断言就知道「屏幕上有东西在放」，比鼠标有没有动可靠得多。音乐播放**不会**持有它，所以听歌时仍会被正常判为离开 —— 这是对的，听歌不算用眼。
- **优先级 1/2 让「离开多久算离开」不用猜**：直接沿用你在「系统设置 → 锁定屏幕」里配的熄屏时间，比任何写死的阈值都贴合你的习惯。

菜单里有一行 `📡 无操作 N分N秒 · 屏幕亮着 · 媒体未播放 · 判定计时中`，把当前的原始信号摊开显示 —— 想确认「这次为什么没暂停」看这行就够了。

### 调阈值

菜单 →「🚶 离开判定」，可选 3 / 5 / 8 / 10 分钟，默认 5 分钟。

存储键：`awayThresholdSeconds`（`defaults write com.zephyr777.restreminder awayThresholdSeconds -int 600`）。

### 怎么验证（不依赖真人离开）

真人坐在电脑前会不停产生输入事件，没法靠静置复现「离开 10 分钟」。所以留了一个调试注入口：

```bash
echo 400 > /tmp/rr_fake_idle   # 伪装成「已空闲 400 秒」
```

## 🖥️ 强制熄屏模式

菜单里打开「🖥️ 到点强制熄屏」后，到点行为从「只发通知」变成：

```
到点 → 全屏提醒动画（5 / 8 / 15 秒可选）→ 显示器熄屏 → 你回来 → 自动重新计时
```

**动画时间轴**（默认 8 秒）：

| 时刻 | 画面 |
|---|---|
| 0.00s | 深色径向渐变背景淡入 |
| 0.08s | 眼睛背后的冷色光晕浮现，之后持续呼吸 |
| 0.18s | 眼睛图标 spring 弹入 |
| 0.38s | 「该休息眼睛了」自下浮起 |

| 0.85s | 底部进度条开始线性走满 |
| 8.00s | 进度条走满 → 文字/图标淡出，循环影片淡入 |

实际效果见 `sleep-overlay-preview.png`。

**「强制」的边界（有意为之）：**

- 默认走的是**伪熄屏** —— 屏幕不关，播一段循环呼吸画面（见下一节）。
- 真熄屏用的是 `pmset displaysleepnow` —— **只关显示器，不锁屏、不休眠整机**，动一下鼠标就回来，所以不会丢失任何工作。
- 动画期间按 **Esc** 可以取消（动画照常播完，只是不做后续动作）。底部有一行很淡的提示。
- 休息结束后会自动等待：等你动鼠标回来时计时器自动归零重新开始，不会出现「刚唤醒又被提醒」的死循环。
- 多显示器时所有屏幕都会被遮罩，内容只显示在主屏。

**调试入口**（源码里，启动前在 `/tmp` 放标记文件）：

## 🎬 循环休息画面（伪熄屏）

提醒动画播完后，屏幕不再直接黑掉，而是落进一段 **15 秒无缝循环的呼吸光晕**，
屏幕上显示 **5 分钟倒计时**，倒完自动结束；随时动一下鼠标或按 Esc 也能提前结束。

**为什么不能「真熄屏 + 循环播放」：** `pmset displaysleepnow` 会把显示器真正断电，屏幕不亮就没地方播视频。这两件事物理上互斥，只能二选一。默认走「伪熄屏」—— 屏幕不黑，播呼吸画面，视觉上一样安静，但能顺带引导呼吸。

菜单里两项控制它：

| 菜单项 | 作用 |
|---|---|
| 🖥️ 到点强制熄屏 | 总开关。关掉就只在到点时发个通知 |
| 🎬 循环休息画面（不熄屏） | 开 → 播循环影片；关 → 回到原来那种真·关显示器 |

`assets/rest-loop.mp4` 缺失时，菜单项会置灰并标注「缺少影片文件」，行为自动退回真熄屏，**不会崩**。

**退出条件**（任一即可）：

- **倒计时走完** —— 屏幕显示「休息完成」，2 秒后自动收起
- 按 **Esc**
- 鼠标 / 键盘连续有动作 **2 秒**（要求连续，防误触）

**收起时的过渡**（0.8 秒）：整窗淡出 + 内容轻微放大 5%（像「散开」而不是「被关掉」），
曲线 `(0.4, 0.0, 0.2, 1.0)` —— 起步缓、中段快、收尾极缓，不会有任何突变。

**顺序是这里唯一容易做错的地方：必须先淡出、淡完再停播放器。**
反过来先 `stopLoopVideo()` 的话，`AVPlayerLayer` 会立刻变黑、露出纯背景色，
看起来就是「跳一下」；同时播放器必须被闭包持有到淡出结束 ——
`AppDelegate` 会把 `overlay` 置 nil，不捕获的话播放器先被释放，画面同样会中途变黑。

倒计时时长在菜单「⏳ 休息时长」里选 **3 / 5 / 10 分钟**，或「不限时（手动结束）」。

退出后计时清零 —— 你已经休息过了，重新开始算。从菜单「🌙 预览完整流程」进来的不算真休息，退出时不会动计时。

**屏幕上的两行字**：中间偏下是剩余时间（等宽数字，`04:59` 这种），最底部一行是退出提示。
两行都由 `CATextLayer` 画，不含在影片里 —— 影片里任何文字都不能有，AI 生成中文必糊且不可修复。

**影片怎么做的、想换成 AI 生成的：** 见 `SEEDANCE-LOOP-PLAN.md`。

`assets/rest-loop.mp4` 是**用 `assets/render-breath.swift` 逐帧渲染**出来的：
1920×1080 / 60fps / 15 秒 / 900 帧。一共四层：

| 层 | 作用 | 关键点 |
|---|---|---|
| 核心光球 | 中央亮核 | 峰值 alpha 0.44 → 0.86 |
| 花瓣 | 12 片径向拉长的光斑，随呼吸向外绽开 | **只当隐约底纹**（alpha 0.055 → 0.145）；15 秒恰好转过 2π/12，图案与自身重合 → 循环点对得上 |
| 外辉光 | 长尾，给画面一点氛围 | 强度压得很低，太强会把整幅画面均匀提亮、变灰 |
| 星尘 | **18 颗**小光点各绕小轨道游动 | 密度低、单颗大而亮（半径 6.5~14.5px），要的是「稀疏但可辨认的颗粒」 |

三个让它「看着对」的关键：

- **中心往白里带**（`alpha > 0.55` 之后逐渐趋向白光）。纯青色叠在深底上只会像一层雾；
  **白心 + 彩色外缘**才有「发光核心」的观感 —— Apple Watch 正念就是这个路子。
- **花瓣要压住浓度**。切向半轴得够大（`atP = sPetal × 0.72`）才不会露暗隙，
  但浓度太高就变成「一朵实心的花」，粒子感全没了。现在只给 0.055 → 0.145 当底纹。
- **星尘讲究「稀疏而清楚」**：颗数少（18）、单颗大（6.5~14.5px）、亮度高（0.46 → 0.88）、
  衰减快（LUT k = 2.10，让颗粒边界更利落）。反过来「多而暗」只会糊成一层噪点。

呼吸曲线 `w = 0.5 − 0.5·cos(2πt/15)`，两端速度都为 0，循环点不会有顿挫。

重新生成：

```bash
cd <项目目录>
swiftc -O -o /tmp/render_breath assets/render-breath.swift
/tmp/render_breath | /opt/homebrew/bin/ffmpeg -y \
  -f rawvideo -pixel_format rgb24 -video_size 1920x1080 -framerate 60 -i - \
  -c:v libx264 -profile:v high -level 4.2 -pix_fmt yuv420p -crf 16 \
  -movflags +faststart assets/rest-loop.mp4
```

900 帧约 12 秒渲染完（按行多线程）。想看某一时刻的静帧效果：

```bash
/tmp/render_breath --preview 7.5 /tmp/peak.png     # 7.5 秒 = 呼吸最盛态
/tmp/render_breath --preview 0   /tmp/rest.png     # 0 秒    = 静息态
```

早期还有一版用 ffmpeg `blend` 合成的，留作备份在 `assets/rest-loop-v1-blend.mp4`。

**技术要点五条：**

1. **播放器必须用 `AVQueuePlayer` + `AVPlayerLooper`**。不要监听 `didPlayToEndTime` 再 `seek(to: .zero)` —— 每次循环会闪一帧黑。另外 `AVPlayerLooper.loopCount` 是**只读**的（表示已循环次数），不要在创建后去赋值。
2. **影片只做背景，文字由代码叠**。AI 生成中文必糊且不可修复，所以循环影片里没有任何文字 —— 倒计时和底部提示都是 `CATextLayer` 画的。
3. **淡出内容层前必须先 `removeAllAnimations()`**。入场动画用的是 `fillMode = .backwards` + `isRemovedOnCompletion = false`，留在层上的动画会一直把 `opacity` 顶回 1，直接改模型值会被它盖掉，症状是「淡不出去」。
4. **倒计时别用「每秒减一」**。`Timer` 每次触发都会晚几毫秒，误差会累积 —— 实测 60 秒的倒计时跑成了 **73 秒**。改成记录一个「截止时刻」，每次用 `deadline.timeIntervalSinceNow` 重算剩余就精确了（修完实测正好 60 秒）。
5. **每秒更新 `CATextLayer.string` 要关掉隐式动画**（`CATransaction.setDisableActions(true)`），否则每次更新都会被淡入淡出动画拖一下，看起来在闪。倒计时字体用 `NSFont.monospacedDigitSystemFont` —— 等宽数字跳动时宽度不变，不会左右抖。

## ⚠️ 必须知道的坑

### 1. Bundle ID 不能再用 `com.antigravity.restreminder`

**症状**：进程正常运行、`statusItem.isVisible` 返回 `true`，但菜单栏里**完全看不到图标**。

**原因**：这个 ID 曾被旧版 LaunchAgent 以「直接执行 `Contents/MacOS/RestReminder` 二进制」的方式注册过，macOS 因此把它登记成 launchd 非托管后台项。之后即使改用 `open` 启动，应用也拿不到窗口服务器会话 —— 表现为状态栏窗口永远停在 `win=(0, -22, 56, 22)`、`window.screen == nil`，系统从不给它做布局。

**解决**：Bundle ID 已改为 `com.zephyr777.restreminder`。**不要改回去。**

### 2. LaunchAgent 必须用 `open -a` 启动，不能直接跑二进制

```xml
<!-- 正确：通过 LaunchServices 启动，拿到完整 GUI 会话 -->
<key>ProgramArguments</key>
<array>
    <string>/usr/bin/open</string>
    <string>-a</string>
    <string>~/Applications/RestReminder.app</string>
</array>
```

直接执行 `Contents/MacOS/RestReminder` 会让 launchd 把它当成后台守护进程，**复现上面第 1 条的同样症状**。

### 3. 熄屏后「等用户回来」的判断不能只看 idle

**症状**：屏幕熄灭后日志反复刷 `屏幕已锁定，转入等待唤醒` → `检测到已从熄屏唤醒，计时自动重置`，一秒一次连着清好几次零。

**原因**：退出等待的条件原本只写了 `idle < 3`（最近 3 秒内有输入）。而熄屏瞬间系统本身会产生一些杂散事件，idle 立刻归零 —— 明明屏幕还黑着，却被当成「人回来了」，于是清零 → 下一 tick 又判成离开 → 再清零，来回抖。

**解决**：退出条件加上「屏幕真的亮回来了」：

```swift
let screenBack = !PresenceDetector.isDisplayAsleep() && !PresenceDetector.isScreenLocked()
if screenBack && idleSec < 3 { /* 才认为用户回来了 */ }
```

另外注意 macOS 自动熄屏时通常**同时上锁**，所以判定顺序要把「屏幕熄灭」放在「锁屏」前面，否则菜单会显示成「屏幕已锁定」，那并不是用户实际做的动作。

> 顺带一提：`pmset displaysleepnow` 触发的强制熄屏在这台机器上只能维持 1 秒左右（系统检测到活动就立刻亮回来），所以拿它测「熄屏」不可靠。真实的自然熄屏会稳定保持到用户回来。
